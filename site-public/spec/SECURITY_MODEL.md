# BuildSeal Security Model

## Goals

- Artifact integrity: detect tampering after pack creation
- Provenance: link artifact to repository, commit, and build
- Offline verification: no external service required
- Vendor independence: verify without trusting BuildSeal

## Non-Goals

- BuildSeal does not prevent malicious builds
- BuildSeal does not verify source code integrity
- BuildSeal does not replace a PKI or CA infrastructure

## Trust Assumptions

- The signing key is not compromised at pack creation time
- The governance file accurately reflects authorized signers
- The verifier binary is obtained from a trusted source

## Known Limitations

### Key Compromise

If the signing key is compromised after pack creation,
an attacker can produce backdated packs that appear genuine.

BuildSeal currently has no transparency log or trusted timestamp.
This means retroactive forgery cannot be ruled out if a key is later compromised.

Mitigation (planned): RFC 3161 trusted timestamp embedded in pack.
Mitigation (planned): Optional blockchain anchor via --verify-anchor.

### Timestamp Trust

Pack timestamps are generated by the build system.
A compromised build environment can produce arbitrary timestamps.

Without an external timestamp authority, the sealed time cannot be independently verified.

### Trust Root Bootstrap

The governance file is created by BuildSeal at setup time.
The first-time trust assumption is: the governance file was not tampered with during delivery.

Users who require stronger trust should pin the public key fingerprint independently
(DNS TXT record, GitHub profile, or out-of-band channel).

### Verifier Binary Trust

The verifier binary is distributed via GitHub Releases.
Users should verify the binary hash before use.

Published SHA-256: see release page.

## Threat Model

| Threat | Mitigated | Notes |
|---|---|---|
| Pack content tampering | Yes | HASH_MISMATCH on verify |
| Signature forgery without key | Yes | Ed25519 |
| Governance file tampering | Yes | manifest hash covers governance |
| Key compromise after signing | No | No transparency log yet |
| Malicious build environment | No | Out of scope |
| Backdated pack creation | No | No trusted timestamp yet |
| Verifier binary compromise | Partial | Hash published on release page |

## Verification Guarantees

When isc_verify returns GENUINE:

- The artifact matches the hash at seal time
- The signature was produced by the governance key
- The governance file has not been modified since sealing
- The pack identity is consistent

When isc_verify returns MODIFIED:

- At least one of the above checks failed
- The artifact must not be trusted

## What BuildSeal Does Not Guarantee

- That the build environment was not compromised
- That the signing key was not compromised before or after sealing
- That the timestamp in the pack reflects the actual seal time
- That the source code is free of vulnerabilities
